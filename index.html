选题介绍：我们做了什么

一句话：一个嵌在项目里的「计算机课助教」，接入豆包大模型，只回答学习相关问题，会多轮追问，无关闲聊礼貌拒答。

功能清单

  • 课程答疑人设：专门回答前端、Java 后端、计算机网络、全栈开发等学习问题；
  • 范围约束：游戏、娱乐、闲聊、生活琐事等无关问题，礼貌说明并引导回到学习话题；

💡 为什么选这个方向（差异化，不和别人撞）
大部分组会做「通用聊天机器人」或「普通电商客服」。我们贴本门计算机课的场景，提示词约束和拒答边界最容易讲清楚，评委和同学一听就懂，Demo 也更稳定。

全局架构与 Key 安全

动手前先讲清：一次提问是怎么走完整条链路的。

网页前端输入问题 · 展示回答
→
后端 /api/chat带 Key 转发
→
豆包方舟接口OpenAI 兼容格式
→
答案原路返回前端追加气泡
⚠️ 为什么 Key 不能放前端？
请求必须带 API Key，而网页代码公开——按 F12 就能看到。Key 放前端等于把家门钥匙贴在门上，别人能拿去刷你的免费额度，甚至产生欠费。
🔑 正确做法
Key 只放在后端 .env，前端只把问题发给自己的后端，由后端带 Key 去请求模型。思路和连数据库一样：密码不进前端。
🚫 三条红线
  • Key 不写进 AGENTS.md；
  • 不提交 Git（.env 必须进 .gitignore）；
  • 不截图发群，展示时打码成 sk-****。

领豆包 Key 与连通测试

豆包模型在火山方舟（Ark）平台调用，新用户每个模型有一定免费调用额度，0 成本学习。

1注册火山引擎并实名认证

进入 火山方舟控制台，注册账号并完成实名认证。

2开通要用的对话模型

控制台 →「开通管理」→ 选一个对话模型（如 Doubao-Seed 系列）→ 开通服务。未开通前可先用免费额度，开通后仍优先消耗剩余免费额度。

先开通模型再调接口。没开通对应模型就调用，会报模型无权限 / 不可用，容易被误以为是代码写错。
3新建 API Key 并复制（本组实操截图）

左侧「API Key 管理」→ 蓝色「创建 API Key」→ 起名字 → 创建后立刻复制。地址：ark.volcengine.com/apikey。

▲ 本组在方舟「API Key 管理」创建的 Key（页面 Key 已打码，名称：zyx-api-key-20261125151919，所属项目 default）

本组 Key（展示已脱敏）：ark-ff492a1c-****-****-****-65c0f，完整原文只保存在后端 .env，不进课件、不进 Git、不发群。

🔒 Key 一般只显示一次，复制后先粘到 .env 或记事本，关掉弹窗就看不到原文了。
⏳ 本组踩坑：页面提示「保存成功，变更预计五分钟生效」。刚创建完立刻调用会返回 401 鉴权失败，等几分钟再测即可，别误当成代码写错。
4确认 model 填什么（方舟重点）

调用时 model 字段填推理接入点 EP ID（在「在线推理 / 开通管理」里创建接入点后复制），形如 ep-202406040****-*****；部分公共模型也可直接填模型 ID。

⚠️ 方舟和硅基流动不一样：model 不能随便写一个模型名字，必须填控制台里有效的接入点 EP ID（或已开通的模型 ID），否则会 404。

具体可用模型与接入点以控制台「开通管理 / 在线推理」页面为准，模型版本会随平台更新。

先 curl 验一次 Key 通不通

curl 就是在命令行发一个 HTTP 请求。先测通，才能分清是 Key 问题还是代码问题。方舟接口兼容 OpenAI 格式。

curl --request POST ^
  --url https://ark.cn-beijing.volces.com/api/v3/chat/completions ^
  -H "Content-Type: application/json" ^
  -H "Authorization: Bearer YOUR_ARK_API_KEY" ^
  -d "{\"model\":\"【填入你的接入点 EP ID】\",\"messages\":[{\"role\":\"system\",\"content\":\"你是计算机课程助教，只解答计算机、编程、网络相关问题\"},{\"role\":\"user\",\"content\":\"解释一下 CORS 跨域\"}]}"
✅ 返回一大段 JSON，里面有 "content":"你好！我是……" 的中文回答，就说明 Key、模型和额度都没问题。

核心实现：五步走

1Key 写进后端 .env（不加引号、不留空格）
ARK_API_KEY=ark-你的豆包Key
ARK_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
ARK_EP_ID=你的方舟接入点EP ID
2后端接口 /api/chat 做三件事

收前端发来的 messages 数组 → 带上 Key 转发给豆包方舟 → 把回答原样返回前端。

3system 提示词：约束助教人设与边界
你是一名计算机课程助教，只回答前端、Java 后端、计算机网络、全栈开发相关的学习问题；
回答尽量通俗、分点说明，必要时给一个小例子。
与课程学习无关的问题（游戏、娱乐、闲聊、生活琐事等），请礼貌说明你只负责课程答疑，
并引导对方提出学习相关问题，不要编造答案。
4多轮对话：维护 messages 数组

模型本身不记事。所谓「记得上文」，是每次请求都把之前的对话一起发过去。每轮把用户消息和 AI 回复都 push 进数组。

5页面：输入框 + 发送按钮 + 消息区

发送后先显示用户气泡，等待期间提示「正在思考…」，接口返回后再追加 AI 回答。

🧠 调参数小抄
temperature 越高越发散（聊天 0.7，查资料 0.2）；max_tokens 太小会「话说到一半断掉」，调大即可。

换平台：只改三个值

同一个页面和接口，只换「钥匙」和「门牌号」，体会 OpenAI 兼容的好处。

参数豆包方舟（主）硅基流动（对比）
baseURLhttps://ark.cn-beijing.volces.com/api/v3https://api.siliconflow.cn/v1
model接入点 EP ID（ep-xxxx）deepseek-ai/DeepSeek-V4-Flash
apiKey方舟 ARK_API_KEY硅基流动 Key
 
// 之前（豆包方舟）
baseURL = "https://ark.cn-beijing.volces.com/api/v3";
model   = "你的接入点 EP ID";

// 现在（硅基流动）
baseURL = "https://api.siliconflow.cn/v1";
model   = "deepseek-ai/DeepSeek-V4-Flash";
// apiKey 换成另一平台的 Key，其余代码完全不动
💡 火山方舟兼容 OpenAI SDK：只改 base_url、model、api_key 少量配置即可接入。
换平台报 404，先检查 baseURL 末尾路径是否完整，以及 model 填的是有效 Model ID 还是正确的 EP 接入点。

踩坑速查表

现象原因解决
401Key 错 / 少写 Bearer / 带了空格换行；本组遇到：新建 Key 未满 5 分钟生效重新复制 Key，请求头写成 Authorization: Bearer ark-xxx；刚创建的 Key 等 5 分钟再测
模型无权限 / 不可用对应模型没在方舟「开通管理」开通回控制台开通该模型服务，再重试
402 · 余额不足免费额度用完，或未开通模型查看额度消耗；或先换另一个平台
404本组遇到：model 填成了模型名，没填接入点 EP ID；或 baseURL 路径不全方舟 model 填控制台接入点 EP ID，逐个字符核对 model 与 baseURL
429请求太频繁被限流（公共接入点有 tpm 限制）加几百毫秒延迟，减少连续点击
CORS 报错前端直连模型接口，Key 也暴露了改走自己的后端 /api/chat 转发
一直思考后超时网络不通，或改 .env 后没重启后端先用 curl 测通，再回前端排查
回答说一半断掉max_tokens 太小调大该参数
🧠 排错顺序：先 curl 测 Key → 再测后端接口 → 最后看前端，从里往外查。

答辩三问与总结

现场答辩三问（准备好口语版答案）

问题回答要点
① 为什么 Key 不能放前端？前端代码公开，F12 就能看到；放出去别人能盗用额度甚至欠费。所以 Key 只放后端 .env，由后端转发。
② 多轮对话为什么要把历史消息一起发？模型本身不记事，每次请求都是独立的；把历史 messages 一起带上，模型才能结合上文回答。
③ 换个平台改哪几个值？为什么只改这几个？只改 baseURL、model、apiKey 三个值。因为豆包方舟等主流平台都兼容 OpenAI 接口格式，地址结构、请求体、返回结构一致，业务代码不用动。

验收清单

  • Key 只出现在后端 .env，前端源码、文档、Git 里都搜不到；
  • curl 能返回豆包中文回答；
  • 页面能提问并显示回答，等待时有「正在思考…」；
  • 追问「我刚才问了什么」能答上来；
  • 切到另一平台后页面照常对话；
  • Key 改错一位时，页面给出友好提示而不是白屏。
🔑 Key 是钥匙，不是作业——谁的额度谁的，别借用别人的 Key。
